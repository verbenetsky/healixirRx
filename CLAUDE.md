## Project overview

healixirRx / "pharmacyStore" is a native Android app (Kotlin, Jetpack Compose) for finding nearby
pharmacies, checking drug/stock availability, and placing orders. Single Gradle module: `app`.
Package root: `com.example.pharmacystore`.

## Build & run

Standard Android Gradle project (Windows, use `gradlew.bat` from the repo root):

```
gradlew.bat assembleDebug          # build debug APK
gradlew.bat installDebug           # build + install on connected device/emulator
gradlew.bat test                   # unit tests (JVM, app/src/test)
gradlew.bat connectedAndroidTest   # instrumented tests (app/src/androidTest, needs a device/emulator)
gradlew.bat test --tests "com.example.pharmacystore.SomeTest"   # single unit test class
```

There is no lint/ktlint config beyond `kotlin.code.style=official` in `gradle.properties`; rely on
`gradlew.bat lint` for Android Lint if needed.

Test coverage today is just the default boilerplate (`ExampleUnitTest`, `ExampleInstrumentedTest`)
— there is no real test suite to run as a regression check yet.

### Required local config

- `MAPS_API_KEY` is read from a Gradle property (currently hardcoded directly in `gradle.properties`,
  not in `local.properties`) and exposed via `BuildConfig.MAPS_API_KEY` and an AndroidManifest
  placeholder for Google Maps/Places.
- `app/google-services.json` (Firebase config) must be present for the app to build/run; it is
  currently untracked (not committed) in this checkout.
- `local.properties` needs `sdk.dir` pointing at the Android SDK (auto-generated by Android Studio).

## Architecture

Layered, feature-folder structure under `app/src/main/java/com/example/pharmacystore/`:

- `data/remote` — Retrofit DTOs and `remoteApi/*Api` interfaces (Retrofit service definitions).
- `data/local` — Room: `db/` (multiple separate `RoomDatabase`s: `PharmacyDatabase`,
  `DrugSearchDatabase`, `ShoppingCartDatabase`, `LocationDatabase`), `dao/`, `entities/`, plus
  `mediator/` for Paging 3 `RemoteMediator`s (`PharmaciesRemoteMediator`, `DrugRemoteMediator`) that
  page server results into Room and track pagination via `RemoteKeys*` tables.
- `data/mappers` — DTO ⇄ Entity ⇄ domain-model mapping extension functions (`toPharmacyEntity()`,
  `toDomain()`, etc.) — follow this naming convention when adding new mappers.
- `data/repository` — `*RepositoryImpl` classes implementing the interfaces in `repo/`. Pattern: wrap
  suspend calls in `runCatching { }` and return `Result<T>`; expose reactive reads as `Flow`/`StateFlow`
  built from Room DAOs; current Firebase user id is read from `FirebaseAuth` directly inside the repo
  (`auth.currentUser?.uid`), not passed in from the ViewModel.
- `repo/` — repository interfaces consumed by ViewModels (DI binds against these, not the impls).
- `domain/model` — plain domain models + `toEntity()`/`toDomain()` extensions used by repositories.
- `di/` — Hilt modules, one per feature/concern (`NetworkModule`, `PharmacyModule`, `AuthModule`,
  `DataStoreModule`, `FirebaseModule`, `LocationModule`, `OrdersModule`, `ShoppingCartModule`,
  `DrugRepositoryModule`, `PlaceModule`, `RepositoryModule`, `DbModule`). Binding modules are
  `abstract class` + `@Binds`; provider modules are `object` + `@Provides`. `App.kt` is the
  `@HiltAndroidApp` Application class that inits Firebase and Places.
- `ui/<feature>/` — one folder per screen/flow (`auth`, `home`, `map`, `orders`, `pharmacies`, `drug`,
  `shoppingcart`, `summary`, `profileScreen`, `profileSetUp`, `settings`, `theme`). Each feature is
  typically a `@Composable` screen file + a `@HiltViewModel`.
- `common/` — cross-cutting Compose/navigation helpers: `AppNavHost.kt` (single source of truth for
  all routes/nav graphs), `Scaffold.kt`, `Gradient.kt`/`GradientRoot.kt` (per-screen background
  gradients keyed by nav graph/route), `Utils.kt` (misc helpers: distance calc, address formatting,
  `Throwable.toMessage()` for user-facing error strings, navigation debug loggers).

### Networking

Two separate Retrofit instances are wired in `di/NetworkModule.kt`, disambiguated with Hilt
qualifiers:
- `@KtorRetrofit` → `PharmacyApi`/`DrugApi`, pointed at a custom backend (currently a LAN IP,
  `http://83.168.69.87:8081/` — expect to need updating per-environment).
- `@DrugRetrofit` → `OpenFdaApi`, pointed at `https://api.fda.gov/`.

Moshi (with `KotlinJsonAdapterFactory`) is the JSON converter for both. `Throwable.toMessage()` in
`common/Utils.kt` is the standard place new network error types get translated into user-facing text.

### Navigation

`AppNavHost.kt` defines everything: the `Screen` sealed class (route strings + typed `route(...)`
builders for routes with arguments) and the `NavGraphs` enum (`CHECK_IF_LOGGED_IN_GRAPH` →
`AUTH_GRAPH` → `MAIN_GRAPH`, with `SHOPPING_CART_GRAPH` nested inside `MAIN_GRAPH`). ViewModels are
frequently scoped to a nav graph rather than a single screen via
`hiltViewModel(navController.getBackStackEntry(<graph route>))`, so several screens in the same flow
(e.g. drug search → pick package → cart) share one `ShoppingCartViewModel`/`DrugViewModel` instance.
When adding a screen, add a `Screen` entry, register it inside the right `navigation { ... }` block,
and decide deliberately whether its ViewModel should be screen-scoped or graph-scoped.

### Auth

Firebase Auth is the identity provider, supporting both email/password and phone (SMS) sign-in, with
optional phone-based MFA enrollment (`AuthRepositoryImpl`). `AuthGate`/`AuthGateViewModel` and
`CheckIfUserLoggedIn` decide where the user lands on launch. Email and phone identities can be linked
to one account (`LinkEmailViewModel`).

### Paging

Pharmacy and drug lists use Paging 3 (`androidx.paging`) with `RemoteMediator` + Room as the local
cache, keyed by per-entity `RemoteKeys*` tables that store the next page key. Location-dependent
queries (nearby pharmacies) read the current device location from `LocationRepository.location`
(a `StateFlow`) at load time rather than threading it through paging params.

### ViewModel conventions

ViewModels generally expose:
- `StateFlow` for persistent UI state (often via `.stateIn(viewModelScope, WhileSubscribed(5_000), ...)`
  wrapping a repository `Flow`).
- A `MutableSharedFlow` (`replay = 0`, `extraBufferCapacity = 1`) exposed as `events` for one-shot UI
  events (toasts, navigation triggers), emitted with `tryEmit`.
- Repository calls wrapped in `runCatching`/`Result`, with failures mapped to an `Error` UI state or
  an event rather than thrown.
